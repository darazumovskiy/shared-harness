# Артефакты: как писать документ, который читается с первого раза

Применять, когда пишешь или переписываешь документ для людей: README, гайд, описание окружения, отчёт, описание MR. Читатель — коллега, который не сидел в задаче и не знает твоих сокращений.

## Правила

1. **Смысл сохраняется полностью.** При переписывании ни один факт, число, путь, команда, имя таблицы или поля не пропадает. Меняется форма, не содержание. Факт, который расходится с кодом или файлами на диске, — исправить по ним, не выдумывать.
2. **Техника — структурой, а не абзацем.** Три и больше технических сущностей (сервисы, порты, файлы, команды, поля, шаги) — маркированный или нумерованный список, таблица или вложенный список. Цепочка «A → B → C → D» — нумерованные шаги или схема в блоке кода. Команды — в блоках кода, по одной на строку, над блоком одна фраза «что делает».
3. **Один абзац — одна мысль.** Абзац про пять разных вещей — это пять абзацев или список. Строка длиннее ~150 символов почти всегда означает, что её надо разбить.
4. **Заголовки ведут читателя.** Первые две-три строки документа — что это и зачем нужно, простыми словами. Дальше разделы по темам. Внутри раздела — сначала суть в одну фразу, потом детали.
5. **Простой язык.** Полные предложения с подлежащим и сказуемым. Термин расшифровывается при первом упоминании в документе. Своих сокращений нет.
6. **Инструкции без личных данных.** Документ должен работать у любого читателя. Свои id, учётки, пути вида `~/work/...` в шагах инструкции — заменить на плейсхолдеры (`<userId>`, `<почта>`, `<корень воркспейса>`) и на способ получить такое значение (какой скрипт, какая команда). Конкретные значения допустимы только как пример того, что проверялось («проверено на игроке `807471`») — не в шагах.
7. **Только то, что нужно читателю.** Убрать упоминания чужих веток и задач, побочных исследований, историю разработки («сначала упало, потом починили»). Если факт из истории нужен — оставить факт без истории. Дата проверки — одной строкой в начале документа.
8. **Никаких следов правки.** Не писать «раньше», «теперь», «переписано», «после переезда». Никаких разделов «альтернативы», «открытые вопросы», «trade-offs».
9. **Ссылки работают.** Каждая относительная ссылка после правки проверена: файл по этому пути существует. Заголовки разделов, на которые ссылаются другие документы, сохраняются.
10. **Секретов в документе нет.** Значения ключей, паролей, токенов, секретных путей не вписываются — только имя переменной и где её взять.

## Проверка перед сдачей

- Строк длиннее ~150 символов не осталось (исключение — строки таблиц; широкую таблицу лучше разбить на несколько узких).
- Каждая относительная ссылка существует.
- В тексте нет своих учёток, id и путей в шагах инструкции, нет значений секретов.
- Прочитать документ целиком как новый читатель: понятно ли с первого раза, что это, зачем и что делать.
