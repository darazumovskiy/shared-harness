# shared-harness

Скиллы для ИИ-агентов, которыми я делюсь с сообществом.
Скилл — это файл с инструкцией, которую агент читает и выполняет, когда вы вызываете его командой в чате.
Скиллы написаны в открытом формате [Agent Skills](https://agentskills.io): его понимают Cursor, Claude Code, Codex и другие агенты.

## Что внутри

| Скилл | Команда | Зачем |
|---|---|---|
| [clearly](skills/clearly/SKILL.md) | `/clearly` | Агент пишет так, чтобы текст поняли с первого прочтения |
| [current-task](skills/current-task/SKILL.md) | `/current-task` | Агент помнит большую задачу между разговорами |

## clearly — понятный текст

Агенты любят сжимать мысль в ёмкие термины и стрелочки.
Пишущему так короче, а читающему приходится расшифровывать.
Скилл запрещает это: агент рассказывает, что происходит, простыми словами и полными предложениями.
Перечни файлов, команд и шагов он оформляет списком или таблицей, а не строкой через запятую.

Три способа вызвать:

- «следуй /clearly» — агент пишет в этом стиле до конца разговора;
- «перепиши /clearly» — агент переписывает указанный текст, не теряя ни одного факта;
- «повтори /clearly» — агент пересказывает свой последний ответ понятнее.

Для документов — README, отчётов, описаний MR — есть отдельный чеклист: [reference/artifacts.md](skills/clearly/reference/artifacts.md).
В нём, например, правила «одна мысль на абзац», «в инструкции нет личных путей и учёток», «каждая ссылка проверена».

Агент может подхватить этот скилл и сам, когда видит, что вы просите написать текст для людей.

## current-task — память о большой задаче

Каждый новый разговор агент начинает с нуля.
Если задача длинная, её приходится заново объяснять: что решили, где остановились, что дальше.
Скилл хранит эту память в обычных файлах внутри проекта.

Как это устроено:

1. В проекте лежит файл `.cursor/tasks/current`. В нём одна строка — путь к папке текущей задачи.
   Путь к этому файлу — просто договорённость, его можно поменять в `SKILL.md` под свой агент.
2. В папке задачи лежат файлы памяти:

   | Файл | Что в нём |
   |---|---|
   | `INDEX.md` | Задача в двух абзацах и оглавление: какой вопрос в каком документе |
   | `state.md` | Где стоим: что сделано, какой следующий шаг, что мешает |
   | `decisions.md` | Принятые решения с датами; записи только добавляются |
   | `knowledge/*.md` | Проверенные факты о коде, конфигах, багах |

3. При вызове `/current-task` агент читает эти файлы и дописывает в них то, что решили в разговоре, но ещё не записали.
   Потом он коротко отвечает: что за задача, где стоим, какой следующий шаг.
4. До конца разговора агент ведёт записи сам.
   Вы подтвердили предложение — запись в `decisions.md`.
   Сделан кусок работы или сменился план — агент перезаписывает `state.md`.

Если папка задачи есть, а этих файлов в ней нет, агент сам создаёт их при первом вызове.
Если он не знает, в чём задача, — сначала спросит.

Этот скилл агент сам не запускает, только по команде `/current-task`.
Так он не трогает файлы задачи, когда вы его об этом не просили.
За это отвечает строка `disable-model-invocation: true` в шапке `SKILL.md`.
Если ваш агент такую настройку не знает, он её просто проигнорирует.

## Как установить

Скопируйте папку скилла из `skills/` туда, где ваш агент ищет скиллы.
Обычно таких мест два:

- папка в домашнем каталоге — скилл доступен во всех ваших проектах;
- папка в корне проекта — скилл доступен только в этом проекте, и его получат все, кто работает с репозиторием.

| Агент | Для всех проектов | Для одного проекта |
|---|---|---|
| Cursor | `~/.cursor/skills/` | `.cursor/skills/` |
| Claude Code | `~/.claude/skills/` | `.claude/skills/` |
| Codex | `~/.agents/skills/` | `.agents/skills/` |

Для другого агента место для скиллов указано в его документации.

Например, чтобы поставить оба скилла для всех проектов:

```bash
git clone https://github.com/darazumovskiy/shared-harness.git
mkdir -p <папка скиллов вашего агента>
cp -R shared-harness/skills/clearly shared-harness/skills/current-task <папка скиллов вашего агента>/
```

После этого перезапустите агента и вызовите скилл в чате: `/clearly` или `/current-task`.
